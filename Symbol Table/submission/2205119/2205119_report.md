This report documents the design, implementation, verification, and bug resolution for **Offline 1: Implementation of Symbol Table** for CSE 310.

A **Symbol Table** is an indispensable data structure used across virtually all phases of a compiler—specifically during lexical analysis, parsing, semantic type checking, and intermediate code generation. ## 2. Architecture & Class Design

The symbol table architecture is divided into three cohesive, object-oriented classes:

```
+-------------------------------------------------------------+
|                         SymbolTable                         |
|  - current: ScopeTable*                                     |
|  - number_of_buckets: int                                   |
|  - scope_counter: int                                       |
+-------------------------------------------------------------+
                              |
                              | 1 : N (stack / linked list)
                              v
+-------------------------------------------------------------+
|                         ScopeTable                          |
|  - id: string                                               |
|  - parent_scope: ScopeTable*                                |
|  - hash_table: SymbolInfo** (array of bucket heads)         |
|  - number_of_buckets: int                                   |
+-------------------------------------------------------------+
                              |
                              | 1 : N (separate chaining)
                              v
+-------------------------------------------------------------+
|                         SymbolInfo                          |
|  - name: string (private)                                   |
|  - type: string (private)                                   |
|  - next: SymbolInfo* (private)                              |
+-------------------------------------------------------------+
```

### 2.1. `SymbolInfo`
- **Role:** Represents an individual identifier or literal token record stored in the symbol table.
- **Member Variables:**
  - `string name`: Key / symbol name (private).
  - `string type`: Token type or structured signature (private).
  - `SymbolInfo* next`: Pointer to the next collision entry in the hash bucket chain (private).
- **Encapsulation:** Complete getter and setter methods (`getName`, `setName`, `getType`, `setType`, `getNext`, `setNext`).
- **Memory Safety & Stack Protection:**
  - Copy constructor and copy assignment operator are explicitly deleted (`= delete`) to prevent accidental shallow copying and double-free vulnerabilities.
  - The destructor iteratively tears down the `next` chain to eliminate recursion stack overflow on long collision lists.

### 2.2. `ScopeTable`
- **Role:** Represents an individual lexical scope as an open-addressing / separate-chaining hash table.
- **Member Variables:**
  - `string id`: Monotonically increasing unique scope identifier (`"1"`, `"2"`, `"3"`, etc.).
  - `int number_of_buckets`: Number of hash slots in the table.
  - `ScopeTable* parent_scope`: Pointer to the enclosing lexical scope.
  - `SymbolInfo** hash_table`: Dynamically allocated array of pointers (`SymbolInfo*`), each pointing to the head of a linked list.
- **Key Operations:**
  - `Insert(name, type, verbose)`: Hashes `name`, checks for collision duplicates via `Lookup`, and appends the new node to the end of the chain.
  - `Lookup(name, verbose)` / `LookUp`: Hashes `name` and scans the bucket chain. Returns `SymbolInfo*` if found, `nullptr` otherwise.
  - `Delete(name, verbose)` / `Remove`: Unlinks the node from the bucket chain, patches adjacent pointers, nulls out `temp->next`, and safely deletes `temp`.
  - `Print(depth)`: Prints all buckets `1..N` formatted with tab indentations corresponding to `depth + 1`. Formats specialized signatures for `FUNCTION`, `STRUCT`, and `UNION`.
  - Destructor: Deallocates all chains in `hash_table[0..N-1]` and `delete[] hash_table`, printing `\tScopeTable# <id> removed`.

### 2.3. `SymbolTable`
- **Role:** Manages the active hierarchy of nested lexical scopes like a stack.
- **Member Variables:**
  - `ScopeTable* current`: Pointer to the topmost / current scope table.
  - `int number_of_buckets`: Configured bucket capacity passed to every newly created scope.
  - `int scope_counter`: Monotonically increasing counter for assigning unique scope IDs.
- **Key Operations:**
  - `EnterScope(verbose)`: Instantiates a new `ScopeTable` with `parent_scope = current` and advances `current`.
  - `ExitScope()`: Pops the current scope table, reassigning `current = current->getParent()`, while preventing removal of the root scope (`parent == nullptr`).
  - `Insert(name, type, verbose)`: Inserts into `current`.
  - `Remove(name, verbose)` / `Delete`: Deletes from `current`.
  - `Lookup(name, verbose)`: Searches `current`; if not found, traverses up `parent_scope` until either found or reaching the global scope.
  - `PrintCurrentScopeTable()`: Prints `current` at depth 0.
  - `PrintAllScopeTable()`: Iterates from `current` to root, increasing tab indentation with each outer parent.
  - Destructor: Pops and deallocates all scope tables in the chain sequentially upon quitting (`Q`).

## 3. Hashing Algorithm & Collision Resolution

### 3.1. SDBM Hash Function
The hash function implemented is the standard SDBM string hash algorithm mandated by the specification:

$$\text{hash} = \Big(\text{str}[i] + (\text{hash} \ll 6) + (\text{hash} \ll 16) - \text{hash}\Big) \pmod{\text{num\_buckets}}$$

In C++:
```cpp
inline unsigned int SDBMHash(const string& str, unsigned int num_buckets) {
    unsigned int hash = 0;
    unsigned int len = str.length();
    for (unsigned int i = 0; i < len; i++) {
        hash = ((str[i]) + (hash << 6) + (hash << 16) - hash) % num_buckets;
    }
    return hash;
}
```

### 3.2. Collision Handling
- Collisions are resolved using **Separate Chaining** (singly-linked lists).
- When a new key collides with an existing bucket entry, it is appended to the tail of the chain, maintaining FIFO order within the chain.
- Deletions update the predecessor's `next` pointer (or the bucket head) and nullify the deleted node's `next` pointer prior to deallocation.

## 4. Input Commands and Output Formatting

The driver processes the standard command set from the specification:

| Command | Arguments | Behavior | Output Format |
|---|---|---|---|
| `I` | `<name> <type...>` | Insert symbol into current scope | `Inserted in ScopeTable# <id> at position <b+1>, <c+1>` |
| `L` | `<name>` | Search across current and parent scopes | `'<name>' found in ScopeTable# <id> at position <b+1>, <c+1>` or `'<name>' not found in any of the ScopeTables` |
| `D` | `<name>` | Delete symbol from current scope | `Deleted '<name>' from ScopeTable# <id> at position <b+1>, <c+1>` or `Not found in the current ScopeTable` |
| `P` | `A` or `C` | Print all tables (`A`) or current table (`C`) | Tab-indented buckets with parsed type formatting |
| `S` | *none* | Enter a new scope | `ScopeTable# <id> created` |
| `E` | *none* | Exit the current scope (ignored if at root) | `ScopeTable# <id> removed` |
| `Q` | *none* | Quit; destroy remaining scopes | Sequential destruction messages for remaining scopes |

### 4.1. Specialized Type Formatting
The print operation decomposes complex type strings into human-readable compiler annotations:
1. **Functions:**
   - Raw: `FUNCTION INT INT FLOAT INT`
   - Formatted: `<foo,FUNCTION,INT<==(INT,FLOAT,INT)>`
2. **Structures:**
   - Raw: `STRUCT INT n_doors BOOL is_electric STRING brand`
   - Formatted: `<car,STRUCT,{(INT,n_doors),(BOOL,is_electric),(STRING,brand)}>`
3. **Unions:**
   - Raw: `UNION INT n_gears BOOL is_hydrolic_brake STRING brand`
   - Formatted: `<bicycle,UNION,{(INT,n_gears),(BOOL,is_hydrolic_brake),(STRING,brand)}>`
4. **General Identifiers / Literals:**
   - Raw: `VAR`, `NUMBER`, `RELOP`
   - Formatted: `<i,VAR>`, `<23,NUMBER>`, `<<=,RELOP>`

## 5. Audit of Issues & Corrective Fixes

During the code audit against `SymbolTableSpec.pdf`, several critical issues, subtle bugs, and specification deviations were identified and fixed across the codebase:

### Issue 1: One Definition Rule (ODR) Linker Violation (`2205119_scope_table.h`)
- **Diagnosis:** `unsigned int SDBMHash(...)` was defined non-inline inside `2205119_scope_table.h`. If this header were included in multiple translation units (e.g., in multi-file projects, test harnesses, or subsequent Flex/Bison offline phases), compilation fails at link-time with `multiple definition of SDBMHash`.
- **Correction:** Declared `inline unsigned int SDBMHash(const string& str, unsigned int num_buckets)`.

### Issue 2: Linker Error on Standalone Inclusion of `ScopeTable::scope_count`
- **Diagnosis:** `static int scope_count;` was declared in `2205119_scope_table.h` but its definition `int ScopeTable::scope_count = 0;` existed only in `2205119_main.cpp`. Any external program or unit test including the header failed to link with `undefined reference to ScopeTable::scope_count`.
- **Correction:** Utilized C++17 `inline static int scope_count = 0;` and reinforced `SymbolTable` to maintain its own `scope_counter` passed to `ScopeTable`, guaranteeing encapsulation and independent numbering per table instance.

### Issue 3: Missing Specification-Mandated Method Names
- **Diagnosis:** The specification explicitly requires `Delete` in `ScopeTable`, and `EnterScope`, `ExitScope`, `Insert`, `Remove`/`Delete`, `Lookup`, `PrintCurrentScopeTable`, and `PrintAllScopeTable` in `SymbolTable`. The original codebase only defined lower_snake_case variants (e.g., `insert_current_scope`, `remove_current_scope`, `print_this_table`).
- **Correction:** Implemented inline forwarding wrappers for all specification-named methods, providing 100% interoperability with both camelCase/PascalCase test callers and legacy snake_case callers.

### Issue 4: Memory Corruption and Undefined Behavior in `solution.cpp`
- **Diagnosis:** `solution.cpp` contained multiple severe defects:
  1. `delete hash_table;` instead of `delete[] hash_table;` (undefined behavior in C++ runtime).
  2. Recursive `if (parent_scope != nullptr) delete parent_scope;` inside `~ScopeTable()`, destroying all parent scopes when exiting an inner scope.
  3. `int id = bucket_index(name);` shadowed the class member `string id;`, causing print statements to display bucket indices instead of scope numbers.
  4. Empty `int main() {}` body.
  5. `cout << "Destructor\n";` debug logging.
- **Correction:** Completely overhauled `solution.cpp` into a fully working, spec-compliant single-file implementation matching `2205119_main.cpp`.

### Issue 5: Undefined Behavior on Blank / Whitespace Lines in `main.cpp`
- **Diagnosis:** If the input file contained whitespace-only lines (e.g., `"   \r"`), `line.empty()` evaluated to `false`. Then `iss >> command` failed without extracting a character, leaving `command` as uninitialized stack garbage and triggering undefined branch execution.
- **Correction:** Replaced unchecked extraction with:
  ```cpp
  if (!line.empty() && line.back() == '\r') line.pop_back();
  istringstream iss(line);
  char command = '\0';
  if (!(iss >> command)) continue;
  ```

### Issue 6: Rigid Command-Line Argument Requirement
- **Diagnosis:** `if (argc < 3) return 0;` abruptly exited if a user executed `./symbol_table` via standard I/O redirection (`./symbol_table < input.txt > output.txt`).
- **Correction:** Updated argument handling to flexibly support:
  - 2 arguments (`argv[1]`, `argv[2]`): Redirects input and output files.
  - 1 argument (`argv[1]`): Redirects input file; writes to `stdout`.
  - 0 arguments: Reads from `stdin`, writes to `stdout`.

### Issue 7: Potential Stack Overflow in Collision Chain Destructor
- **Diagnosis:** `~SymbolInfo() { if (next != nullptr) delete next; }` used recursive destruction. In deep collision chains, this risks stack overflow.
- **Correction:** Replaced with an iterative traversal that unlinks and deletes chain nodes in $O(N)$ time with $O(1)$ auxiliary stack space.
